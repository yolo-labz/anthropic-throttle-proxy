## Ranked gaps and finite ownership

### G1 — P1: proxy can replay an uncertain generation POST

**F / high confidence (synthetic wire reproduction).** A loopback upstream reads
the entire POST then loses the connection before sending headers. The real
`_forward_with_retry` path sends the identical POST **twice** and returns the
second response. This remains true with `RATE_PUSHBACK_RETRIES=0` and keepalive
hold disabled: it is a different retry mechanism.

Evidence: `src/anthropic_throttle_proxy/forwarding.py:459` transport handoff and
`:494` exception return; `src/anthropic_throttle_proxy/proxy.py:2154`, `:2184`,
`:2235`, `:3480`. History: retry-direct predates the latest client work (`14a17edc`;
`git blame -L 2160,2185 src/anthropic_throttle_proxy/proxy.py`). Existing fallback
tests prove retry success, not safe-to-replay delivery semantics:
`tests/test_forwarding_paths.py:114`, `:355`.

**H / impact:** a provider may already have billed/generated the first request;
client `maxRetries:0` alone cannot enforce one physical provider send through this
proxy. The source counterexample is real; duplicate live billing is **U**.
`clients/transport-fetch-hold/README.md:73` and #312's conservative client fixture
are correctly scoped and are **not** themselves regressed.

**Falsifier:** a counting loopback peer accepts exactly one POST under uncertain
pre-header disconnect while known pre-send connection failures remain recoverable.
**Repair acceptance:** add inverse assertions to the existing forwarding suite;
run `uv run pytest -q tests/test_forwarding_paths.py tests/test_proxy_helpers.py`.
Cover direct and local→central lost replies; distinguish known-unsent, explicit
retryable status and unknown-sent; preserve no retry after committed SSE. Do not
claim upstream idempotency without a provider contract.
**Effort/owner/dependency:** 1–2 focused engineering days; future proxy/transport
owner assigned by coordinator; depends on freezing the uncertain-send policy,
not new quota, credentials or production activation.

### G2 — P1: Desktop session single-flight blocks its own async completion

**F / high confidence (installed-library synthetic reproduction).**
`/home/notroot/.local/share/mimo-desktop-api/app/desktop_session.py:254` is async,
but a same-seed follower calls `threading.Event.wait(timeout=60)` at `:288`.
The SSO owner must resume on that same event loop before `done.set()` at `:312`.
With a synthetic SSO and timeout scaled to 50 ms, the owner succeeds, the follower
blocks **50.20 ms** then returns **None**. No real SSO/session was touched.
The library's SHA-256 is in the runtime receipt; its installed directory is not
a Git checkout, so a vendor commit identity is **U**.

Real callers: `/home/notroot/.local/share/mimo-desktop-api/app/mimo_client.py:73`,
`:211`, `:241` and `/home/notroot/.local/share/mimo-desktop-api/app/desktop_session.py:329` (usage reads share the same refresh path). Installed
`/home/notroot/.local/share/mimo-desktop-api/tests/test_desktop_session.py:11` tests cookie discovery, not concurrent refresh.
**H / impact:** simultaneous chat/meter refresh at cache expiry can stall the
bridge event loop for up to the configured 60 s and falsely report no-session.
The nominal cache TTL is 30 min; actual live occurrence/frequency is **U**.

**Falsifier:** two same-seed asynchronous callers receive the same successful
synthetic cookie with a responsive heartbeat and one SSO call, without a blocking
wait. Include cancellation/failure cleanup so followers never hang.
**Repair acceptance:** add those cases to the existing vendored bridge test tree;
run `(cd /home/notroot/.local/share/mimo-desktop-api && .venv/bin/python -B -m unittest discover -s tests)`

### G3 — P1: bounded prefix capture drops late usage, weakening gauge accuracy

**F / high confidence for cap/parser; forwarding integration not replayed.**
`src/anthropic_throttle_proxy/forwarding.py:355–362` stores only the **first** 1 MiB;
its `:299` docstring incorrectly suggests it can capture final usage even on long
responses. Prepared-SSE path `src/anthropic_throttle_proxy/proxy.py:2722–2745`
uses the same prefix policy. Both feed parsing at `src/anthropic_throttle_proxy/proxy.py:4082`, `:4368`;
`ratelimit.py:482` returns zero for missing output usage. A synthetic stream with
output usage after the cap yields input **11**, output **0** for the prefix versus
output **37** for the full stream. No live generation loss is claimed.

**H / impact:** long responses undercount tokens, costs and throughput; “best
real metrics” cannot mean exact fleet tokens/s on that path. Observe calibration
already marks `capture_cap` unknown (`prospective_calibration.py:229`); that honest
protection does not restore ordinary history token totals.
**Falsifier:** actual normal **and** prepared-SSE loopback forwarding retain exact
wire bytes while accounting a usage event after 1 MiB; missing/encoded/malformed
usage stays explicitly incomplete, never inferred as complete zero spend.
**Repair acceptance:** extend existing forwarding/keepalive/parser tests and run
`uv run pytest -q tests/test_forwarding_paths.py tests/test_keepalive_hold.py tests/test_ratelimit_usage.py tests/test_prospective_calibration.py`.
Use bounded incremental event parsing or a bounded tail strategy that still
retains initial Anthropic input usage; do not retain the entire response or only
fix the displayed gauge. Repair-check must bound retained memory independently
of stream length.
**Effort/owner/dependency:** 1–2 days; proxy telemetry owner with gauge owner;
depends on a shared accounting-completeness contract; not on a higher provider cap.
