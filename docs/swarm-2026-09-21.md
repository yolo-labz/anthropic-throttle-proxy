## Hypothesis and observed root causes

**Hypothesis:** the proposal conflates internal content blocks with native protocol fields, filters/slices turns incorrectly, matches endpoints by substring and joins unchecked values; its only call site also cannot reach the reported chat-completions endpoint.

Falsifier: execute the new counterexamples against exact original source, including actual `proxy.handler` → forwarding → synthetic HTTP, and check whether original behavior already preserves the required request. It does not: **65 failures, 31 passing controls**.

1. `kept[:-1]` sliced the already-filtered list, deleting the valid preceding user request when the original final turn contained only thinking. Filtering now decides per original index and appends the final placeholder, never replacing an unrelated kept turn.
2. Native `tool_calls` were flattened/deleted while `role=tool` and `tool_call_id` survived. Native fields and tool-result messages are now retained, including empty/null assistant content and empty tool results. The reported 1210 concerns `content[]` types; it is not evidence that native tool calls are unsupported.
3. A numeric `text` entered a string join and raised `TypeError`; nested malformed blocks could also be dropped or stringified. The rewrite is transactional: invalid/unknown block shapes return the original bytes, including any earlier valid turns. Upstream remains responsible for rejecting unsupported input.
4. `'/chat/completions' in target` matched OpenAI, arbitrary hosts, query strings and suffix paths. Matching now checks parsed HTTPS scheme, exact `api.z.ai` hostname, default/443 port and exact `/api/coding/paas/v4/chat/completions` path. Query parameters are allowed without changing endpoint identity. No routing destination is changed.
5. `args[:400]`, `str(body)[:4000]` and truthiness-based argument selection discarded meaningful data. Recognized internal calls/results now retain complete strings/JSON values, including `false`, `0`, `null`, `{}`, `[]` and `""` arguments.
6. **Additional integration blocker:** ingress only buffered/normalized `POST /v1/messages`; it then appended that path to a lane URL. The reported `/api/coding/paas/v4/chat/completions` bypassed the normalizer entirely. The repair removes that ineffective call and normalizes in `forwarding._forward_once`, using each attempt's actual destination. Direct retries share that function. Unknown central targets get the original body; a direct Z.AI retry gets normalization. Headers are copied and Content-Length refreshed case-insensitively when the body changes.

Caller trace: `proxy.handler` → `_forward_with_retry` → `_try_forward` → `forwarding._forward_once`; `_retry_direct_once` returns through the same seam. `_forward_once_into_sse` is separate but reachable only under exact `path == 'v1/messages'` (prepared keepalive hold), not the chat-completions path. Ingress remains path-preserving and needs no new provider-conversion logic.
